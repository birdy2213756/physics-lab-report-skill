- `python scripts/build_prompt.py --check`：检查豆包提示词由共同规则和两种模式的规则完整生成。
- `python -m unittest discover -s tests -v`：检查数值、单位等价、周期计数、确认门槛、无效输入、拟合选点、图像输出及本地链接。
- 技能创建工具的 `quick_validate.py`：检查技能元数据与结构。
- 数字示波器脚本生成的结果与公开JSON一致；比较图记录中的点与计算结果一致。

教学模拟数据仅出现在工具接口说明和数值测试中，均标明用途，不作为实测案例。

## 人工场景验收

| 场景 | 应有行为 | 第一版检查方式 |
|---|---|---|
| 课前波尔共振预习 | 原理300～500字＋3问，不写实测结论 | 示例正文、公式与字数检查 |
| 普通课后报告 | 默认无独立实验原理，仍保留计算公式 | 示例和报告规则评审 |
| 用户或教师要求原理 | 在实验目的前增加原理 | 可选章节路由规则评审 |
| 新的文字、截图或表格数据 | 完整核对，确认前不计算结果 | 共同规则评审；脚本门槛测试 |
| 用户已明确确认数据 | 不重复问，只处理确认范围 | 历史文字示例与规则评审 |
| 已确认数据后来改变 | 重新确认变化，重算依赖结果 | 规则评审；未确认输入拒绝测试 |
| 单位冲突、周期跨度不明 | 标出疑点，暂停相关计算 | 规则评审；错误单位和周期测试 |
| 仪器精度、重复记录缺失 | 不编数值不确定度，说明依据不足 | 报告示例与规则评审 |
| FFT或思考题缺页 | 标待补，不以理论或预习问题冒充 | 报告示例与规则评审 |
| 没有计算或作图工具 | 标未程序复核，提供手绘数据和指导 | 三入口共用规则评审 |
| 部分数据拟合 | 需要原因与确认，保留所有点 | 脚本选点测试 |

这里的“规则评审”是人工检查技能指令，不是独立模型实验。尚未对Codex、Claude Code与豆包逐一完成端到端实测；不同版本、模型、上下文和附件能力会影响实际行为。安装说明对照官方文档，但不宣称已在每个平台实际安装验证。
