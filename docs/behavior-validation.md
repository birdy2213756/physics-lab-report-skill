# 独立Codex回答测试

2026-10-11，测试目标为复现约定格式与写作习惯。使用Codex CLI 0.162.0-alpha.17.2及账户默认模型设置，在独立临时会话中安装项目技能；以只读环境限制文件写入，允许读取规则及必要计算。共运行15个会话，覆盖8类场景及修正后的复测；1次基线超时，其余会话交付回答，交付不等于每次均符合所有要求。没有向Claude Code或豆包发送测试。

测试任务为自包含文字材料，包含已确认示例数值；没有使用原始聊天附件或个人信息。可复用场景见[行为测试输入](behavior-cases.json)。每次要求实际读取技能及对应规则，以正常学生交付内容作答。人工检查章节、确认范围、来源声明和公式，另用程序复核数值与中文字数。

## 发现与修正

基线来自提交`062adf295964fb92c8d7c03869358cdf321421c1`。一次完整报告反复尝试读取扫描教材，240秒内没有交付；另一次声称已经核对教材正文，但记录只证实渲染和输出base64，未证实实际阅读。这两项没有计作通过。

第一轮加入材料优先及无指定题目的处理规则后，报告能交付且主要计算正确，但三份小结只有451、468、519个中文字，均漏了FFT待补。随后明确小结的检查范围和已提及子实验清单，再复测。另外发现将数值改写为汉字的表达问题，补充沿用阿拉伯数字与标准单位的要求。随后一次报告小结643字且数值表达恢复正常，但把“无思考题答案”误读为省略整章；该次章节格式未通过，进一步明确仍须保留思考题标题及“本次无指定思考题”。

报告小结按中文正文计数，不计标题、数字、表格及独立公式。“约600字”常规交付检查范围为540～660个中文字；材料确实不足时允许有说明的缩短。三个小结字数来自不同场景，不能作为同一场景的三次稳定性重复测试。

最后一次普通报告复测的小结为588字，数值使用阿拉伯数字和标准单位，五个固定章节均保留，默认无独立原理。材料来源为当次文字记录，没有声称核对未查看的教材页面。这是修正后的一次符合主要验收项的交付，仍需更多重复测试才能评价稳定性。
